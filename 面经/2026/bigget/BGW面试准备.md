**1. 装饰器 Decorator**
场景：给自动化测试用例加上耗时统计，跑完自动打印耗时，方便发现慢用例。
```python
import time

def timing(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f"此用例耗时 {end - start:.2f}s")
        return result
    return wrapper

@timing
def test_login():
    pass

test_login()   # 输出：此用例耗时 0.12s
```
可展开讲的深度点：
- 本质：`@timing` 是语法糖，等价于 `test_login = timing(test_login)`。
- 原理：函数是一等对象，wrapper 是闭包，捕获了外层 func。
- 加分项（一句话带过）：想保留函数名等元信息，可在 wrapper 上加 `@functools.wraps(func)`。

**2. 生成器 Generator（生成器表达式）**
场景：逐个产出 1~n 的三次方，惰性求值，不一次性算完。
```python
g = (i ** 3 for i in range(1, 6))

for x in g:
    print(x)   # 依次输出 1, 8, 27, 64, 125
```

**3. 列表推导式 List Comprehension**
场景：同样的三次方，用列表推导式一次性算完存进列表。
```python
l = [i ** 3 for i in range(1, 6)]
print(l)   # [1, 8, 27, 64, 125]
```
对比：g 是生成器对象——惰性求值、用多少算多少、省内存；l 是列表对象——一次性全部算好存内存。两者只差一个括号（`()` vs `[]`）。

**Q7. 印象最深刻的问题与解决方式**（二面）

**作答：**
批量分配交易费用时，尾差算法开发使用四舍五入。
举例：有一个总交易费用N作为需要拆分，总共10笔订单，每笔订单的股数不同。
第2-第10笔订单的交易费用=本笔股数*（总交易费用/总股数），四舍五入
第1笔订单=总交易费用-SUM（第2到第10笔费用加总）

这里存在两个问题。1、第1笔订单减法可能为负，实际也有比较异常的负交易费用触发结算侧告警2、四舍五入算法导致不同订单的尾差过大3、没有参考业界尾差通用算法，以及系统里面已存在的算法

正确的解法：1、找业界通用算法，统计系统内需要批次拆分的尾差算法。统一使用通用算法
2、算法如下：算出来平均交易费用后，向下取整，然后第1到10笔订单使用股数*平均交易费用，向下取整。因为向下取整，所以仍然有尾差，但是需要将尾差拆分为最小单位0.01，然后一笔一笔将0.01将每一笔订单上面加，假设是0.12，则第一第二笔订单+0.02，其他订单+0.01。
